# 3.13.0-pod.1.2.1 — TigerPOD frees tags of spools deleted in Studio

- Format and new associations no longer refuse tags that only look associated. A spool deleted in Studio can leave a tombstone or a link to a spool that no longer exists; both are now removed or replaced in the same conditional cloud batch. A live spool, or a link to a live spool, still protects the tags.
- Format on tags whose spool documents are only tombstones becomes a full blank erase of both tags, ready for a new association.
- The Format tile now formats a known pair properly instead of running the blank erase, and a linked maker chip (Bambu Lab and similar) can have its link removed from the same tile.
- A new spool whose tags no spool owns (blank TigerTag pair, blank NFC chip, Bambu Lab or other maker chip) now opens the association wizard straight after the automatic scan, instead of stopping on the Read tags report.
- Every release page now opens with the notice that this firmware is unofficial.

Tested on a real 3.5B scale. Not yet validated on the 3.5 without the B.
